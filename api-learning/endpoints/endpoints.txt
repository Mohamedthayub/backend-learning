3. REST API Conventions
What is a REST API Convention?

A REST API convention is a standard way of designing API endpoints.

Instead of creating random URLs, you follow common rules used by companies like Netflix, GitHub, Stripe, Amazon, and many others.

A well-designed API should be:

Easy to understand
Consistent
Predictable
Easy to maintain
Resource-Based URLs

In REST, URLs represent resources (nouns), not actions (verbs).

Resource examples
Users
Products
Orders
Categories
Reviews
Books

Think of a resource as a table or collection in your database.

Example:

Products
---------
Laptop
Phone
Keyboard
Mouse

The resource is products.

So the endpoint should be:

/products
Why Not Use Verbs?

Many beginners write APIs like:

/getProducts
/createProduct
/deleteProduct
/updateProduct

This is not RESTful because the HTTP method already describes the action.

Instead of putting the action in the URL, use the appropriate HTTP method.
Bad:

GET /getProducts
POST /createProduct
DELETE /deleteProduct

Good:

GET    /products
POST   /products
DELETE /products/:id

The URL tells what resource you're working with, and the HTTP method tells what action to perform.

Complete REST API for Products
HTTP Method	 Endpoint	     Purpose
GET	      /products	          Get all products
GET	     /products/:id	      Get one product
POST	 /products	      Create a product
PUT	    /products/:id	      Replace a product
PATCH	/products/:id	  Partially update a product
DELETE	/products/:id	  Delete a product

Notice that only the HTTP method changes, while the URL remains consistent.

Use Hyphens Instead of Spaces or Underscores

Good:

/user-profile
/order-items

Avoid:

/user_profile
/UserProfile

Hyphens improve readability and are the common convention for REST APIs.
--------------------------------------------------

----------------------------------

REST API Design Rules to Remember
Use nouns, not verbs, in URLs.
Let the HTTP method describe the action.
Use plural resource names (/products, /users).
Use route parameters (/products/:id) to access a specific resource.
Use lowercase URLs.
Use hyphens for multi-word resources (/order-items).
Keep endpoint naming consistent across your entire API.
